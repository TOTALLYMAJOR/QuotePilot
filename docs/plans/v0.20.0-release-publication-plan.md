detail for the `QPR-*` tasks. GitHub issues may mirror these tasks but cannot

## Operating constraints

- Preserve unrelated work. Stage only exact named paths after reviewing the
  cached diff.
- Packaging tasks review and publish existing work; they do not authorize
  opportunistic content changes. A required repair gets its own `plan:task`
  scope and focused validation.
- Never use a dirty-worktree result as exact-candidate, CI, deployment, provider,
  production, or human proof.
- Never place `.env`, credentials, local graph data, generated browser output,
  or other machine-local artifacts in a release slice.
- Complete each task before starting a dependent task. A failed gate returns to
  the smallest owning slice.
